# Dog-owner flyer landing and WhatsApp enquiry proposal

Status: proposed for approval; do not merge or deploy to production yet. Existing flyer QR destinations are unchanged.

## Landing journey assessment

`/dog-owners` is suitable as an optional destination for future senior-dog awareness flyers. The opening message fits an education-first campaign, with signs to discuss with a veterinarian, research limitations, product-specific evidence, and a separate nutritional supplement route. It is less direct than the catalogue for readers already seeking a product or partners applying to the programme. Match the destination to the flyer purpose; do not replace catalogue links globally.

The implementation adds an enquiry link beside the opening education action, a second enquiry section after the safety boundaries, and contact actions in both the mobile header and drawer. Desktop navigation uses the same shared link. Links open an editable WhatsApp draft at the existing business number; they do not send messages. Clinical questions remain directed to veterinarians. No diagnosis, dosing or treatment claims have been added.

## Lightweight attribution proposal

Proposed pilot links (examples for review, not authorisation to print or redirect):

- https://pets.peptide-south-africa.com/dog-owners?campaign=senior-dog-flyer-pilot
- https://pets.peptide-south-africa.com/dog-owners?campaign=senior-dog-partner-pilot

Only the exact public codes registered in `src/lib/enquiryCampaign.ts` are accepted. Unknown, duplicate, empty, personal-looking and unrelated parameters are ignored. Register a separate public code per approved print batch or partner campaign. Never use customer identifiers, phone numbers, email addresses or health information in URLs or registered codes.

The recognised code is included as `Campaign reference: …` in the draft. It is only available on the current `/dog-owners` URL. Reloading that URL retains it; navigating away or removing the query does not preserve it. A code may be copied or shared, so it describes the link used, not a verified individual or partner identity. No commission or partner eligibility is inferred.

This feature adds no cookies, local/session storage, visitor IDs, forms, analytics events, account lookups or database writes. It does not change existing site analytics. URL codes may already appear in hosting/access logs and existing analytics; keep them public and nonpersonal. WhatsApp handles messages under its own terms once opened/sent.

## Measuring the pilot

Count received messages containing each reference as campaign-tagged enquiries. Keep aggregate counts per code and period; no new customer records are needed for this comparison. If the number of flyers distributed is known, report received tagged enquiries / flyers distributed as the observed enquiry rate. Draft edits, unsent messages and copied links limit attribution. An opened draft or click is not a confirmed enquiry or purchase. This implementation does not measure scans, visits, clicks, orders or end-to-end conversion rates. Any later event analytics should be separately reviewed for consent and minimised fields; the existing `trackPets` helper attaches session/account identifiers and is deliberately not used here.

## Approval and validation

Run `npm ci`, `npx playwright install chromium`, `npm run test:enquiry`, `npm run build`, `npm run lint`, `npm run check:boundary`, and `npm run test:seo`.

Browser regressions cover 320, 390, 768, 1280 and 1440 px, link destination and editable text, minimum touch target, keyboard focus, drawer visibility, no horizontal overflow, scoped axe accessibility checks, allowlisting, duplicate parameters and non-persistence. Existing boundary and SEO checks protect the educational language and canonical/prerender behaviour.

Approval is needed before merge/production deployment and before changing any existing flyer destination. Preview deployments, when generated by the branch integration, are for review only.

Local verification passed: seven Playwright tests (including scoped axe checks), build with 26 prerendered routes, lint, research boundary and SEO authority. This environment uses Node 24; the added GitHub workflow runs Node 22 as required by the repository.
